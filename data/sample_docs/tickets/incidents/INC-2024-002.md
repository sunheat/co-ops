# INC-2024-002 — Duplicate margin run after scheduler restart

| Field | Value |
| --- | --- |
| Incident ID | INC-2024-002 |
| Date | 2024-02-02 |
| Severity | MEDIUM |
| Affected Modules | Batch Scheduler, Margin Service |
| Status | CLOSED |

## Timeline

- 02:10 — `margin_run` started for ASX.
- 02:25 — The scheduler host restarted; on recovery the scheduler started a
  second execution for the same business date.
- 02:50 — The duplicate run failed on the primary key of `margin_results`,
  but reconciliation had briefly consumed rows from the interrupted first
  run.

## Impact

Reconciliation output for ASX was delayed by one hour while the affected
run was rerun cleanly. No client-facing figures were published from the
interrupted run.

## Root Cause

The scheduler did not check the current state of `margin_runs` before
restarting a job, so an in-flight run could be duplicated.

## Resolution and Follow-ups

- Scheduler now checks `margin_runs.status` and resumes or skips instead of
  blindly restarting.
- The batch-job-failure runbook was updated to require marking orphaned
  `RUNNING` rows as `FAILED` before any restart.
