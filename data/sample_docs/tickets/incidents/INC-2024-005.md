# INC-2024-005 — Acknowledgment loss during custodian maintenance

| Field | Value |
| --- | --- |
| Incident ID | INC-2024-005 |
| Date | 2024-03-05 |
| Severity | HIGH |
| Affected Modules | Fulfillment Adapter |
| Status | CLOSED |

## Timeline

- 2024-03-05 09:00 — A custodian began an unannounced maintenance window.
- 2024-03-05 09:00–10:30 — Four settlement instructions were sent; the
  custodian processed two but its acknowledgments were lost, and two were
  never received.
- 2024-03-05 11:00 — Support correlated the adapter log with the custodian
  status page and identified the window.
- 2024-03-05 12:30 — All four instructions were resent with their original
  identifiers; the custodian deduplicated the two already fulfilled.

## Impact

Settlement for the four instructions was delayed by half a day; no
duplicate settlements occurred thanks to identifier-level deduplication.

## Root Cause

The adapter had no counterparty-health awareness, so lost
acknowledgments during custodian maintenance were indistinguishable from
transport failures until manual correlation.

## Resolution and Follow-ups

- An acknowledgment-timeout alert was added so stuck instructions raise a
  ticket automatically.
- The stuck-fulfillment runbook was updated with the counterparty-health
  check as an early step.
